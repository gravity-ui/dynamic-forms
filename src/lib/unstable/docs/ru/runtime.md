# Рантайм

Как рендерер живёт во время работы: регистрация узлов, начальные значения, валидация, ошибки, события и патчи.

## Жизнь узла

`SchemaRendererNode` подписан на конфиг, ошибки, режим, имя, патчи, настройки и схему. Он собирает подсхему по JSON Pointer, регистрирует поле `final-form`, кладёт в контекст `input` и `meta` и рисует entity. Если лейаут есть и сущность не `independent`, он оборачивает entity снаружи.

### Имя и указатель

- Имя — путь `final-form`: `user.name`, `tags[0]`.
- `schemaPath` — указатель схемы: `#/properties/user/properties/name`, `#/properties/tags/items`.

Составная сущность создаёт детей новым `SchemaRendererNode` и сама связывает обе координаты. `schemaOverride` сливается поверх схемы по указателю (с учётом `$ref`). `withoutRegister` не регистрирует поле — так группы `ObjectEntity` рисуют заголовок без собственного значения.

### Начальное значение

`default` пишется при регистрации, пока родитель не пуст (пусто — `undefined`, `null`, `''`, `0`, `false`; корень всегда непуст). Обязательный объект или массив без `default` получают `{}` или `[]`. Поэтому `default` вложенного поля сработает, только когда родитель уже существует — его значение должно появиться раньше.

### Приведение значения (coerceInitialValues)

| Тип схемы                   | Как приводится уже лежащее значение                                               |
| :-------------------------- | :-------------------------------------------------------------------------------- |
| `number` / `integer`        | `'12'` → `12`. Нечисловая строка — ошибка типа. Пустая строка `''` — ошибка типа. |
| `boolean`                   | `'true'` и `1` → `true`. `'false'` и `0` → `false`.                               |
| `string`                    | Число и boolean → строка.                                                         |
| `object` / `array` / `null` | Без изменений.                                                                    |

## Валидация

Узлы своих валидаторов `final-form` не держат. Валидатор один — на служебном поле. Каждое поле указывает это служебное поле в `validateFields`, поэтому любое изменение дёргает только его. Результат для `final-form` — строка `'error'` или `false`; тексты полей лежат в `srState.errors` и видны через `meta.error`.

`validateOnBlur` у рендерера должен совпадать с `<Form validateOnBlur>`: `runValidate` блюрит служебное поле и опирается на этот флаг, чтобы перезапустить проверку.

### Слои ошибок

Совпадающий путь перекрывается более поздним слоем. Объект в ошибке разворачивается на дочерние имена.

| Слой | Источник                   | Когда писать                                                   |
| ---: | :------------------------- | :------------------------------------------------------------- |
|    1 | `regularErrors`            | Внешние, низкий приоритет. `addExternalErrors`, ошибки Monaco. |
|    2 | JSON Schema                | `json-schema-library`, Draft-07, плюс `stringNumber`.          |
|    3 | `nodeParameters.validator` | Свой валидатор узла. Может вернуть промис.                     |
|    4 | `priorityErrors`           | Внешние, высокий приоритет. Перекрывают тот же путь.           |

Текст JSON Schema ищется по цепочке: `errorMessages` на схеме из самой ошибки → схема узла по `schemaPath` → словарь рендерера → сырое сообщение библиотеки. Значение — строка или функция от ошибки; для `required` и `dependencies` допустим словарь по имени свойства.

### Свой валидатор

Сигнатура: значение узла и весь `values`. Возврат — строка этого поля, объект сообщений детей, `undefined` или промис того же. Промис кэшируется по значению и схеме (кэш живёт до смены `schema` или `name`). Пока он не завершён, форма тоже «проверяется»; после резолва валидация запускается снова. Подробный пример — в [Расширении](./extension.md#свой-валидатор).

Сообщение видно, когда поле `touched` или submit не прошёл. Перед `form.submit` рендерер увеличивает `submitCount` и шлёт `Submit`; `Card` и `Accordeon` на этом событии раскрываются, если ошибка есть у узла или у его потомков.

## События

`useSchemaRendererState` по умолчанию слушает все события; можно сузить до `Error` по `name` или `Patch` по `schemaPath`. За один dispatch подписчик получает не больше одного уведомления.

| Событие         | Триггер                                    | Кто получает                                                         |
| :-------------- | :----------------------------------------- | :------------------------------------------------------------------- |
| `Schema`        | Новая ссылка `schema`                      | Все подписчики. Копия, патчи, ошибки, кэш сброшены.                  |
| `Patch`         | `addSchemaPatches` / `removeSchemaPatches` | Узлы, чей `schemaPath` — префикс изменённого пути (с учётом `$ref`). |
| `Error`         | Набор сообщений изменился                  | Узлы с изменившимся сообщением по их `name`.                         |
| `Config`        | Новая ссылка `config`                      | Все подписчики. Проверка не перезапускается.                         |
| `ErrorMessages` | Новый словарь текстов                      | Все. Тексты применятся на следующей проверке.                        |
| `Mode` / `Name` | Сменился режим или путь корня              | Все подписчики.                                                      |
| `Settings`      | `size`, `view`, coerce, jsonDefault        | Все подписчики.                                                      |
| `UserContext`   | `updateUserContext`                        | Все подписчики.                                                      |
| `Submit`        | Перед оригинальным `form.submit`           | Все. `submitCount` + 1, Card и Accordeon раскрываются на ошибке.     |

## Патчи схемы

Рабочая схема — глубокая копия пропа `schema`; патч меняет копию, исходный проп не трогается. Новая ссылка `schema` или `name` копию сбрасывает.

- **merge (по умолчанию).** Каждый лист пишется по своему пути, массивы сливаются по индексам, пустые `{}` и `[]` — no-op. Адрес — `schemaPath` или `name` зарегистрированного поля.
- **replace: true.** Подменяет узел по `schemaPath` целиком (для `#` — всю схему). Нужен, чтобы заменить массив (`enum`, `required`) или удалить ключ.

`removeSchemaPatches` снимает патч с тем же путём и глубоко равной схемой (`schema: true` — все патчи узла), восстанавливает затронутые листья из оригинала и переприменяет остаток. Учтите: ключи, которых не было в оригинале, при снятии патча не удаляются (см. [Нюансы](./limitations.md)).

API императивных операций — `useSchemaRendererTools`, примеры — в [Расширении](./extension.md#динамическая-схема).
