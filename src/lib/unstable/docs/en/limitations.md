# Caveats and limitations

Behavior verified against the code and with throwaway tests. Items are grouped by category; some should be resolved before the API stabilizes (see [Open questions](#open-questions)).

- **Discrepancy with JSDoc** — the code comment promises something other than what happens.
- **Limitation** — important behavior to account for.
- **Looks like a bug** — the behavior looks like an error.
- **To verify** — not covered by tests, needs confirmation.

## Discrepancies with JSDoc

| Topic                  | What actually happens                                                                                                            | What to do                                                                    | Where in code                                |
| :--------------------- | :------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------- | :------------------------------------------- |
| `readOnly`             | JSDoc: "control disabled, value visible". In fact, in form mode the node is not rendered, but the field registers and validates. | Fix the JSDoc, or disable visibly via `flags.disabled` instead of `readOnly`. | core/types/schema.ts, SchemaRendererNode.tsx |
| `title`                | JSDoc promises a fallback to the property name. `EntityTitle` without `title` returns null — no heading.                         | Fix the JSDoc; always set `title` if a label is needed.                       | schema.ts, EntityTitle.tsx                   |
| `writeOnly`            | JSDoc: "hides the value in the overview". In fact the whole node, with its heading, is omitted in the overview.                  | Clarify the wording in the JSDoc.                                             | schema.ts                                    |
| `default` / `examples` | JSDoc has TODO(verify). Fact: `default` is set at registration while the parent is not empty; `examples[0]` is a placeholder.    | Remove the TODO, document the real behavior.                                  | schema.ts                                    |

## Limitations

| Topic                                            | What actually happens                                                                                                                                                                       | What to do                                                                  | Where in code                                    |
| :----------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :-------------------------------------------------------------------------- | :----------------------------------------------- |
| `required` and an empty string                   | `required` only checks key presence. `{login: ''}` passes. Clearing a TextInput writes `''`.                                                                                                | Add `minLength: 1` or the `not: {enum: ['']}` trick.                        | get-schema-root-node.ts                          |
| required on a nested object                      | If the object value is absent (`undefined`), neither its `required` nor its children's constraints are checked, and `default` is not applied.                                               | Give the object a value via `flags.required`, `default` or `initialValues`. | get-schema-root-node.ts                          |
| `flags.required`                                 | Pure UI: an asterisk, hiding the reset, initializing `{}` / `[]`. Does not enable validation.                                                                                               | Use together with the parent's real `required`.                             | SchemaRendererNode.tsx, EntityTitle.tsx          |
| `flags.hidden`                                   | Hides the layout via `display: none`, but the field validates and a hidden error blocks submit.                                                                                             | For conditional fields — `if` / `then`, `oneOf` or schema patches.          | LayoutContainer.tsx / .scss                      |
| Flags do not inherit                             | `disabled` on an object does not disable nested fields — each node reads its own flags.                                                                                                     | Set `disabled` on each leaf or patch the schema.                            | SchemaRendererNode.tsx                           |
| `nodeParameters.type` is required                | Without `type` string `entity` / `layout` / `validator` keys are not resolved — the node renders nothing, the validator is silent.                                                          | Always set `type`, easier via `createNodeParametersDefiner`.                | SchemaRendererNode/utils.ts                      |
| `formEntityProps` does not inherit `entityProps` | When `formEntity` is set, `formEntityProps` fully replaces `entityProps` for that mode. Same for layouts.                                                                                   | Duplicate common props in the mode pairs or do not set `formEntity`.        | SchemaRendererNode/utils.ts (getRenderKit)       |
| `$ref` siblings                                  | On render the `$ref` target wins. The Draft-07 validator ignores sibling keywords: `minLength` next to `$ref` is not validated.                                                             | Keep constraints and `nodeParameters` on the target schema.                 | SchemaRendererNode/utils.ts, json-schema-library |
| Patch merge                                      | In merge, arrays merge by index, empty `{}` and `[]` do nothing.                                                                                                                            | To replace an array entirely or delete a key — `replace: true`.             | useSchemaRendererTools/utils/schema-patch.ts     |
| `modeOverride`                                   | Affects only the node itself. Children are rendered by the entity in the renderer's mode.                                                                                                   | For mixed pages set the prop on each leaf or make a custom layout.          | SchemaRendererNode.tsx, ObjectEntity.tsx         |
| `validateOnBlur`                                 | Must match `<Form validateOnBlur>`. A mismatch breaks the restart via `runValidate`.                                                                                                        | Pass a single value to Form and the renderer.                               | useSchemaRenderer/utils/get-run-validate.ts      |
| `useSchemaRendererState` before mount            | If the service field is not registered yet, the hook returns `undefined` and does not retry.                                                                                                | Call inside or after `SchemaRenderer`.                                      | useSchemaRendererState.ts                        |
| Errors not in form state                         | Field texts live in `srState.errors`, not in `form.getState().errors` (only `'error'` of the service field is there).                                                                       | Read errors via `useSchemaRendererState`.                                   | useSchemaRenderer.ts                             |
| External errors do not self-clear                | Those added via `addExternalErrors` do not disappear on field edit.                                                                                                                         | Clear with `removeExternalErrors` manually before the next submit.          | useSchemaRendererTools/utils/external-errors.ts  |
| Error without a layout                           | The error text is rendered by `EntityError` inside the layout. Without a layout only the control highlight shows.                                                                           | Assign at least `transparent`.                                              | layouts/\*                                       |
| Properties outside `order` / `groups`            | Not rendered and not registered, but validated. A `required` error bubbles up to the object.                                                                                                | List all needed properties or remove the extra ones from the schema.        | ObjectEntity.tsx                                 |
| Overview of enum and passwords                   | select / radio / segmented show the raw value in the overview without `enumDescriptions`; a password is open.                                                                               | Set `enumDescriptions`; give a password `writeOnly: true`.                  | overview-entities/\*                             |
| HTML in descriptions                             | `description` and the texts of Alert / Label / TextContent go through `dangerouslySetInnerHTML` unless `RenderHTMLOrMD` is set.                                                             | For untrusted schemas set `userContext.RenderHTMLOrMD`.                     | HTMLContent.tsx                                  |
| Changing `errorMessages` / `config`              | Sends events but does not restart validation. New texts and validators apply on the next validation.                                                                                        | Rely on the next trigger or change the `schema` reference.                  | useSchemaRenderer.ts                             |
| Async validator                                  | Called only when a value is present (always for the root); the result is cached by value; `true` gives an error with no text.                                                               | Return a string or `undefined`.                                             | useSchemaRenderer/utils/parse-errors.ts          |
| Validators in the Spec bridge                    | A string-key `spec.validator` is not found (kit `validators` are empty) — the check is silently skipped. mutators / search / generateRandomValue are not used in `withSchemaRenderer` mode. | Move validators into `config` during migration.                             | transformer.ts, DynamicField.tsx                 |
| Dots in keys                                     | final-form reads `a.b` as the path `a` → `b`. `warnAboutDottedPropertyKeys` only catches legacy DynamicField.                                                                               | Rename keys with a dot in the schema and the value.                         | DynamicField.tsx                                 |

## Looks like a bug

| Topic                              | What actually happens                                                                                                                    | What to do                                          | Where in code                   |
| :--------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------- | :------------------------------ |
| `removeSchemaPatches` and new keys | Removing a patch does not delete keys that were not in the original. In RangeInput, after clearing `from`, `to` keeps the old `minimum`. | Fix the restoration or document it as a limitation. | schema-patch.ts, RangeInput.tsx |
| Validator promise reject           | The promise has no `catch`: a rejection leaves the form in `validating` and yields an unhandled rejection.                               | Do not reject; add error handling.                  | parse-errors.ts                 |
| ObjectEntity group name            | A group's virtual node gets a name with a double dot: `profile..___group0___` (or `.___group0___` at the root).                          | Check the group name template.                      | ObjectEntity.tsx                |
| form.submit wrapper                | Several renderers wrap `form.submit`. Non-LIFO unmounting loses another's wrapper and breaks its `Submit`.                               | Low priority; restore the chain carefully.          | useSchemaRenderer.ts            |

## To verify

| Topic                        | What actually happens                                                                                                                                      | What to do                                               | Where in code        |
| :--------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------- | :------------------- |
| `connectValidate: false`     | No tests or stories. Likely the returned `validate` is attached to a field named `name` (`runValidate` blurs the service field, `validateFields: [name]`). | Verify and document a wiring example.                    | useSchemaRenderer.ts |
| Changing `schema` on the fly | Resets errors, patches, cache, submitCount; recalculation on the next validation.                                                                          | Verify whether an explicit validation restart is needed. | useSchemaRenderer.ts |

## Open questions

1. `readOnly`: document it as hiding, or change the code to a visible disable?
2. Fix the JSDoc for `title`, `writeOnly`; remove the TODO on `default` and `examples`.
3. Fix `removeSchemaPatches` for new keys (the RangeInput case) or document it as a limitation.
4. Handling a reject in the async validator.
5. The double dot in the `ObjectEntity` group name.
6. Confirm and document `connectValidate: false`.
